# Сверка Go и Python `aism`

Общие сценарии (`features/*.feature`) описывают наблюдаемое поведение CLI:
файлы проекта и `ai-skills.yaml` на входе → код выхода и файлы в target на
выходе. Шаги (`test/`) запускают исполняемый файл из `AISM_CLI` и не знают,
на чём он написан, поэтому одни и те же сценарии проверяют обе реализации.

```sh
make conformance           # Go: bin/aism
make conformance-python    # Python: .venv/bin/aism (коммит f89ab47 репозитория InsonusK/ai-skill-manager)
make conformance-compare   # обе, таблица «сценарий → GO / PYTHON», логи в tmp/conformance/
```

Без `AISM_CLI` набор пропускается, чтобы известные расхождения не роняли
`go test ./...`. Конфиги в сценариях используют `settings.target`: корневой
`target` Python не понимает.

Ожидания в сценариях — поведение, которое кажется правильным; какая
реализация его выполняет, видно из сравнения. По всем расхождениям ниже
решено оставить поведение Go.

## Совпадает (11)

Форматы скилов → `{name}/SKILL.md`; исполняемый файл остаётся исполняемым;
`whenToUse` → `when_to_use` только для Claude-target; папка `examples`
копируется и не проверяется; `--dry-run` ничего не пишет; скил, убранный из
источников, удаляется из target; вложенный скил, дубль имени, имя не в
kebab-case — ошибка; чужая папка, не нужная ни одному скилу, не трогается;
ссылка на невыбранный скил без `add_relations` — ошибка.

## Расходится (13)

| # | Сценарий | Go | Python | Оценка |
|---|---|---|---|---|
| 1 | Ссылки внутри скила и между скилами; ссылка на human-dir/flat скил; `add_relations` | Переписывает относительно **файла**: `./docs/x.md`, `../b/SKILL.md` | Переписывает относительно **папки проекта** (конфига): `out/a/docs/x.md`, `out/b/SKILL.md` | Go читается любым markdown-просмотрщиком и не зависит от того, куда положен target. Python работает, только если читатель резолвит пути от корня проекта (агент в корне репозитория), и ломается при переносе target |
| 2 | Ссылка без `.md`, рядом папка `X` и заметка `X.md` | Ведёт на заметку `X.md` (ваше решение) | Ведёт на папку `X` | Go — как Obsidian; на реальном `ai-skills` ссылки имеют в виду заметку |
| 3 | Markdown-ссылка на несуществующий файл | Ошибка, ничего не пишет | Пишет битую ссылку, код 0 (а несуществующая цель **wikilink** — ошибка) | Go: одинаково строг к обоим видам ссылок; Python непоследователен |
| 4 | Битая ссылка в файле, на который скил не ссылается | Ошибка (проверяются все `.md` скила) | Не проверяет | Go строже; Python проверяет, похоже, только файлы, достижимые по ссылкам от главного |
| 5 | Ссылка на несуществующий заголовок (`#якорь`) | Ошибка `missing-anchor` | Якоря не проверяет | Новая проверка Go; на `ai-skills` нашла 45 реальных ошибок |
| 6 | Бейдж `[![img](a)](b)` вне `examples`/`templates` | Ошибка `link-overlap` | Сохраняет | **Решено: Go** — бейджи бывают только в примерах и шаблонах (они исключены из проверок), в тексте скила это ошибка |
| 7 | Одноимённая папка в target без маркера | Ошибка `unmanaged-target`, папка не тронута | **Перезаписывает** и ставит маркер | **Go прав**: Python теряет чужой скил, хотя его README обещает защиту |
| 8 | Повторный sync после удаления файла из скила | Папка заменяется целиком, файла нет | Старый файл остаётся в target | Go: target совпадает с источником; у Python копятся устаревшие файлы |
| 9 | Несуществующий `subpath` | Ошибка `missing-subpath` | Молча пустой выбор, код 0 | Go: опечатка в конфиге видна сразу |
| 10 | Ссылка за пределы папки источника (`../b` при `path: skills/a`) | Ошибка `path-escape` | Идёт по ссылке и загружает `b` как связанный скил | **Решено: Go** — неизвестно, куда ведёт такая ссылка; риск для безопасности |
| 11 | Ссылка на файл вне всех скилов | Копирует в первый ссылающийся скил: `{name}/files/<путь в источнике>`, ссылки ведут туда | Копирует в `{target}/files/<имя>` с warning, ссылку пишет от папки проекта | **Решено: Go** — файл внутри скила с маркером управляется как весь скил, имя по пути в источнике без совпадений |

Детали:
- п. 1 и п. 11 у Python связаны: ссылка на копию в `files/` тоже пишется от
  папки проекта (`out/files/notes.md`).
- п. 3: в Python ошибка `points to a target that does not exist` бывает
  только у wikilink; `[gone](./gone.md)` переписывается без проверки.
- п. 10: сценарий «с `add_relations`» написан через `subpath`, чтобы
  связанный скил был внутри источника; выход за источник — отдельный п. 10.
